# Followup Tracker

记录未完成项、待补证据项、下周继续追踪项。

## 何时触发

- **按需** — 在 `risk-scorer` 之后、`weekly-summarizer` 生成周报前调用

## 数据源

读取以下来源中包含 `followup_needed` 标记的数据：
- `../data/raw/*.json` — 各采集 skill 的输出
- `../data/risks.json` — risk-scorer 中标记需要跟进的条目
- `../data/scratch/*.json` — 临时标记文件

## 工作流程

### 1. 收集待办项
从所有数据源中收集 `followup_needed == true` 的条目：
- 缺少交叉验证的重大事件
- 未解决的矛盾信息
- 风险分超过阈值但可信度不足的事件
- 人工显式标注的追踪项

### 2. 验证待办必要性
使用 LLM 验证每条待办是否确实需要创建：
**仅当以下条件之一满足时才创建待办：**
1. 风险分 > 阈值且缺少交叉验证
2. 矛盾未解决
3. 人工显式标注
4. 未完成的外部数据获取

否则不自动创建。

### 3. 优先级排序
按风险分倒序排列：
- 高风险 + 高紧迫 → P0
- 中风险 + 中紧迫 → P1
- 低风险 / 长期追踪 → P2

### 4. 生成周度待办
为每条待办生成：
- 话题/描述
- 创建原因（缺少验证 / 矛盾 / 高风险）
- 严重程度（P0/P1/P2）
- 截止日期
- 期望方向（如"需找第三方信源验证"）
- 待办置信度（`confidence_to_resolve`）

## 输入参数

- `include_resolved` (boolean, default: false): 是否包含已解决的待办
- `max_items` (integer, default: 20): 最大输出条数

## 输出

写入 `../output/weekly_followup_tasks.md`：
```markdown
# 下周待追踪事项

## P0 - 本周内必须跟进
- [ ] **某国拟加征25%关税** — 风险分 1.7，缺少第三方来源交叉验证
      需找至少2家贸易分析机构报告确认

## P1 - 优先跟进
- [ ] **A公司与B公司技术合作传闻** — 矛盾信息未解决（A说已签约，B说在洽谈）
      需找官方公告确认

## P2 - 持续观察
- [ ] **固态电解质论文比例变化** — 技术路线拐点信号，持续跟踪月报数据
```

## 原则

- 仅当满足条件才创建待办，不编造待办项
- 每条待办附带创建原因和期望方向
- 输出 `confidence_to_resolve` 标记待办置信度
- 已解决的待办默认不输出（除非设置 `include_resolved: true`）
