# Weekly Summarizer

按固定模板生成周报草稿，等待人工审阅后发布。

## 何时触发

- **自动**：每周五 13:00（触发预生成）
- **手动**：按需触发

## 数据依赖

本 skill 依赖以下上游数据源（应在调用前已就绪）：
- `../data/raw/` — 各采集 skill 的原始数据
- `../data/entities_index.json` — entity-dedup 输出的实体索引
- `../data/validation_*.json` — source-validation 验证结果
- `../data/risks.json` — risk-scorer 评分结果
- `../data/pending_followups.json` — followup-tracker 待追踪项

## 生成流程

### 1. 合并已验证事实
从各数据源筛选出已验证（Tier 1-2）的高价值信息。

### 2. 按模板生成
周报模板包含以下章节：

```markdown
# 🗞️ {行业名称}行业周报 | {日期范围}

## 一、本周行业大事记
（概览不超过3个要点）

## 二、政策解读
（政策原文摘要 + 影响分析 + 引用条款编号）

## 三、技术与产品动态
（专利/论文/新产品发布）

## 四、市场与竞争
（市场动态 + 竞争格局变化）

## 五、风险与机遇提示
（风险分 + 机会分 + 可信度）

## 六、下周待关注事项
（来自 followup-tracker）

---
*本报告由行业周报助理自动生成，已通过 source-validation 验证。*
*发布时间：{date} | 数据截止：{date}*
```

### 3. 一致性检查
扫描整份周报草稿，找出逻辑上互斥的陈述：
- 前文说"供应链紧张缓解"，后文说"原材料价格上涨" → 不构成矛盾，合理
- "某公司Q3市场份额上升" vs "该公司Q3营收下降且行业总规模不变" → **矛盾，输出警告**

### 4. 守门规则

- **概览部分不超过3个要点**
- **每个动态必须带有 Tier1 级别的 source-validation 验证锚点**
- **禁止出现未经验证的推测性描述**
- **大事记中称"市场乐观"，风险部分必须对应有悲观信号或标注"无对应风险信号"**
- **原始素材中无明确数据（增速/份额），摘要中不得自行推算**
- **任何"首款""最大""唯一"类断言，必须附带交叉验证结果**

## 输出

生成 `../output/weekly_report_{行业}_{日期}.md`，格式为 Markdown。

## 原则

- 前后不矛盾：跨章节一致性检查
- 不编造数据：原始素材无数据则摘要不可推算
- 守门规则严格执行
- 发布前必须经人工审阅
